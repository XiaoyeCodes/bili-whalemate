# 评论收件箱与自动任务修复

主人评论没有回复的已确认原因是：通知已收取并生成草稿，写入冷却返回 `submission=not-sent` 和恢复时间，但旧控制器将通知标为已处理，后续轮询跳过该通知。此次修复保存未发送草稿，在恢复时间后复用原有任务发送；不会重新调用模型，也不重复占用 AI 生成次数。原任务的日期、配额归属保留，实际完成时间记录在 `ended`。

只有明确未提交且原因为冷却、写入预算或平台暂停的评论才进入重试。`automation.maxCommentSendAttempts` 默认 3，包含第一次发送；达到上限后明确显示停止重试。回复成功、平台拒绝、请求超时、回读结果不明以及进程在发送中退出都不会自动重发。重试前检查功能开关、当前主人身份和原评论的公开状态。关闭功能时保留待发送任务，重新开启后仍须满足恢复时间和尝试次数限制。

通知游标按平台的 `id` 和 `reply_time` / `at_time` 翻页，遵守 `is_end`，不再把游标对象编码为字符串。主人与陌生人功能仍使用各自开关和每日 AI 次数；陌生人超额通知不调用模型，同一人每天只预留一次。评论处理发现账号暂停后，同一轮停止动态和视频写入。

升级须同时更新服务、设置页与 vendored B 站工具并重启应用。已有未发送记录如果没有保存草稿，不会凭空恢复或盲目重发；需要核对原评论和明确未发送的回执后单独恢复。已发布及结果不明的记录保留。无需清空数据库或配额。

本次源码同步包含发布仓库之前缺少的人物卡、碎碎念、写入用量、私信消息批次以及 QQ/B 站文字表情处理依赖。安装器保留目标 profile 和端口，保护 pnpm 共享文件，并为 QQ 配置当前安装的服务地址和图库目录。图库、账号、私聊和日志均不从运行电脑复制进发布代码。

验证覆盖设置持久化、配额、重复通知、同一条消息出现在两个收件箱、冷却、重启恢复、跨日、固定超额通知、功能关闭、模型失败、发送结果不明、图片回读与动态正文回读。完整平台可用性仍取决于登录、额度、审核和网络，测试通过不代表所有环境永远无故障。运行电脑上原来漏回的一条主人追问已恢复，并通过公开评论接口回读确认；私聊、陌生人和动态的本次回归使用隔离测试数据，没有为测试向陌生人额外发言。
